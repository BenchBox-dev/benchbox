# Decision: run the pull-request fast tests on Python 3.14

Date: 2026-10-16
Status: Accepted. Maintainer decision, 2026-10-16.

Related:

- `.github/workflows/ci.yml` (`code-test`, reported through the required `core` check)
- `.github/workflows/trunk.yml` (`fast (ubuntu-latest, 3.12)`)
- `.github/workflows/nightly.yml` (Python 3.11 to 3.14 matrix, 70% coverage gate)
- `tests/unit/test_release_infrastructure.py` (pins this split)

## Decision

The fast unit tests on every pull request run on Python 3.14 with coverage.py's
`sys.monitoring` core (`COVERAGE_CORE=sysmon`). Python 3.12 no longer runs on
pull requests. It still runs the same fast tests after each merge to `develop`
(`trunk.yml`) and nightly with the 70% coverage gate (`nightly.yml`), alongside
3.11 and 3.13.

## Why

- CI should run on the most widely used supported Python version, which the
  maintainer identifies as 3.14.
- The older supported versions already have a planned deprecation schedule:
  Python 3.11 support is removed in October 2027, when 3.11 reaches end of
  life. The pre-merge check follows the version the project is moving toward.
- Branch coverage is on. Before Python 3.14, coverage.py cannot use its
  `sys.monitoring` core with branch coverage and falls back to the slower C
  tracer. On 3.14 the faster core works, which shortens the longest job on
  every pull request. Locally, coverage overhead fell from about 52% to 18%
  of the suite's runtime.

## Accepted risk

Before this decision, three independent reviews of the change raised the same
risk: a failure that happens only on Python 3.12 or 3.11 is now caught after
merge by the trunk or nightly run, not before merge. The maintainer accepted
that risk. A failing trunk or nightly run on an older version is fixed forward
or reverted like any other post-merge failure.

Coverage reported to Codecov comes from 3.14 on pull requests and from 3.12
on `develop`, so Codecov's comparison mixes versions. The 70% gate is enforced
inside the job, and the Codecov upload does not fail the build.

## Revisit when

- A 3.12-only or 3.11-only failure reaches `develop` more than occasionally.
- The deprecation schedule changes which versions are supported.
