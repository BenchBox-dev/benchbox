# Agent attribution on published surfaces

`[COMMIT-IDENTITY-001]` in `AGENTS.md` is the authority. This note records the
mechanism the rule responds to and the trade-off accepted, so the decision is
not argued again from scratch.

## What was observed

Agent-authored GitHub posts ended with a rule and an italic attribution line.
A live instance is the closing comment on PR #1494 (`issue_comment`
5174430128). It ends with a `---` rule, then
`_Generated by [Claude Code](https://claude.ai/code)_`.

Two details make this more than cosmetic:

- **It posts as the maintainer.** That comment's `user.login` is
  `joeharris76` with `author_association: MEMBER`. The footer reads as the
  maintainer announcing that their own comment was machine-generated.
- **The strings differ by surface.** Comments carry
  `Generated by [Claude Code](https://claude.ai/code)`. Pull request bodies
  carry `Generated with [Claude Code](https://claude.com/claude-code)` plus a
  session URL. PR #1494's description and its comment did not match.

## Origin

The agent harness's own operating instructions append the footers. They tell
the agent to end every comment, review, review reply, and issue comment with
the attribution footer, even when the posting tool would add one (the server
strips duplicates). A separate instruction gives pull request bodies the
differently worded variant.

This is the same class as the agent `Co-Authored-By` commit trailer: external
in origin, applied by convention, not by request. `AGENTS.md` already answers
that class: a tool convention is not authorization.

## Why the rule is advisory, not enforced

A commit trailer can be caught: a commit passes through
`.git/hooks/commit-msg`, where `scripts/check_agent_trailers.sh` rejects it. A
GitHub comment has no such chokepoint. The agent calls the GitHub API directly,
and no repository-side control sits in that path. Any mechanical check here
must run after the fact: a workflow that reads posted comments and flags the
footer. It detects but does not prevent. That is a real option, but do not
call it prevention.

## Where the harness setting must live

Claude Code's `attribution` setting (`commit`, `pr`, `sessionUrl`) controls the
commit trailer, the `Generated with [Claude Code]` pull request line, and the
session link. A maintainer's `~/.claude/settings.json` reaches only sessions on
that machine. Cloud sessions on claude.ai/code clone the repository into a
fresh sandbox, so they see neither the user settings nor the local
`commit-msg` hook. The setting is therefore also committed in the project
`.claude/settings.json`, which every session reads. The comment footer comes
from the cloud harness's own instructions and may not follow this setting; the
`AGENTS.md` rule still covers it.

## The trade-off accepted

Suppressing the footer removes the only standing signal that separates an
agent-authored comment from a human one on a post under the maintainer's
account. That cost is accepted deliberately, for two reasons. A footer on every
post is noise that readers stop seeing. A blanket machine marker under the
maintainer's account also misleads about who is speaking. So instead of an
unconditional footer, the rule asks for disclosure **in the text, where it
changes what a reader would do**. For example, when a comment reports what an
agent verified, or when a reviewer would act differently knowing the analysis
was automated.

Two alternatives were considered and not chosen:

- **Unify the two footers into one shorter string.** Keeps a disclosure signal
  and fixes the inconsistency between surfaces, but keeps a standing marker
  under the maintainer's account.
- **Post agent comments from a bot identity.** The strongest option, because
  the account itself carries attribution instead of a line in the body. It
  needs a bot account and token provisioning, so it is out of scope here. If
  that ever lands, revisit this rule, since the account would then do the
  footer's job.
